# Iteration 0.5.3 — yt-dlp subprocess → Python library migration

## Changes detail

| Topic | Before → After | Reason |
|-------|----------------|--------|
| Engine invocation | `subprocess.Popen`/`create_subprocess_exec` running the `yt-dlp` bin in PATH → `yt_dlp.YoutubeDL` library (`asyncio.to_thread` dedicated thread) | user proposed using yt-dlp as a library; progress switched to structured `progress_hooks` dicts (status/downloaded_bytes/total_bytes/speed/eta), no more regex stdout parsing; version and engine governed uniformly by uv.lock |
| Config item | `download.yt_dlp_path` (default `"yt-dlp"`, env `BLDLP_YT_DLP`) → removed | yt-dlp is a Python library dependency (`uv add yt-dlp==2026.07.04`), no PATH executable needed; `/api/config`'s `yt_dlp_path` changed to `yt_dlp_version` (`yt_dlp.version.__version__`) |
| Cancel mechanism | SIGTERM (`process.terminate()`) → `threading.Event` + progress_hook raises `yt_dlp.utils.DownloadCancelled` | threads cannot receive SIGTERM, semantically equivalent: `.part` kept for resume; `_run` handles it via the existing state machine after catching |
| Probing | `subprocess.run --dump-single-json` JSON parsing → `YoutubeDL.extract_info(url, download=False)` | native library extraction, `DownloadError` errors uniformly de-prefixed and converted to `RuntimeError` |
| Final path | stdout regex `Merging/Moving file/Destination` → return value `info["requested_downloads"][0]["filepath"]` | the library return value directly carries the merged/transcoded path, no text parsing needed |
| Merge phase | text lines `[Merger]`/`[MoveFiles]` → `postprocessor_hooks` (`{"status":"started","postprocessor":...}`) | structured events drive `phase=merging` |
| Docker | runtime pip `yt-dlp==2026.07.04` + imageio-ffmpeg → only imageio-ffmpeg | yt-dlp already provided by the uv dependency layer (builder `.venv`), the image no longer needs it installed |
| Progress parameter | `retries: "infinite"` string → `float("inf")` | string causes TypeError in library mode (CLI syntax not universal) |

## Evidence (research phase, real local Bilibili video with `yt-dlp==2026.07.04`)

- Parameter mapping checked item by item: `format`/`outtmpl`(must be relative, absolute would ignore `paths`)/`paths.{home,temp}`/`continue`/`overwrites`/`cookiefile`/`http_headers`/`postprocessors(FFmpegExtractAudio)` all equivalent to the old CLI
- `paths.temp` behavior: under relative templates, `.part` correctly lands in staging (same as `--paths temp:`)
- Pause/resume: first round hook raises `DownloadCancelled` to abort, `.part` kept → second round rerun with same params hits the resume path and completes the merge
- Engine smoke test: real download pause mid-way → resume → done, `out_path` correctly includes the uploader subdirectory; cancel terminal state correct
