# Iteration 1.3.0 — Bangumi (anime/drama/season) support

## Changes

| Topic | Before → After | Reason |
|-------|----------------|--------|
| URL acceptance | `is_bilibili_url` only accepted `/video/…` paths → also accepts `/bangumi/play/ss\d+` (season) and `/bangumi/play/ep\d+` (episode) | `ss1733`-style anime/drama links were rejected with "only bilibili video page URLs are supported"; bangumi play pages are first-class downloadable pages |
| Page metadata on modern bangumi SSR | userscript `pageMeta()` parsed `__INITIAL_STATE__.videoData` → also parses `playurlSSRData` (current-ep `arc.bvid`/`cid`, `supplement.ogv_episode_info`) and `<meta og:title>` (season name) | play-v2/laputa SSR pages no longer ship `__INITIAL_STATE__`, so bangumi links showed "Not a bilibili video page" |
| Season episode list | n/a (unsupported) → `probe_info`/`parse_probe` handle yt-dlp playlist results: each episode becomes a page with its `ep` URL, quality list unions the resolved episode formats | the userscript cannot read Bilibili's season-list API (`@connect` only allows localhost); yt-dlp resolves the season once, and the backend returns the full episode list with per-episode URLs |
| Multi-page download body | `DownloadBody` had `url` + `pages` (int list) → added optional `urls` (string list, parallel to `pages`) | a bangumi season download must create one job per selected `ep` URL (page-based `?p=N` does not apply to bangumi); the frontend sends back the episode URLs discovered by `/api/info` |
| Frontend build tab | parts rendered only from local `pageMeta()` → for seasons, parts (episodes) render from the `/api/info` response and default-check the currently playing episode | the episode list is not present in the DOM, only in the backend probe result |
| Version | 1.2.0 → 1.3.0 | feature release (pyproject + userscript + `/api/health`) |

## Implementation notes

- Both `ep` and `ss` URLs are accepted; only `ss` is treated as a season (whole-episode list). Opening an `ep` page directly behaves like a single-part video.
- Per-episode `ep` URLs pass through the same download pipeline (yt-dlp + quality + resume) as regular videos; `noplaylist` stays in the params because each job now targets a concrete `ep` URL.
- The season probe forces each episode entry to be fully resolved (~seconds per episode, 43 episodes took ~20s for ss1733), which is why the full episode count/URLs are only available in `/api/info` and not from the DOM.
- `parse_probe` keeps the existing single-video output shape; its playlist branch adds a per-page `url` field (only present for seasons).
