# Iteration 0.1.0 — Documentation baseline

First documentation baseline. No code, only requirements and design finalized.

## Changes

- Tech stack | undecided → uv + Python FastAPI + yt-dlp (PATH configurable) + ffmpeg + SQLite | environment already has uv/Python/yt-dlp, FastAPI fits subprocess and SSE
- Frontend form | undecided → single-file Tampermonkey userscript, floating panel isolated with Shadow DOM | requirement is "operate Bilibili pages in the browser + persistent floating panel + GM cross-domain", userscript beats MV3 extension (see design.md)
- Progress sync | undecided → SSE push-primary + 2s polling fallback | EventSource native support, one-way read-only with low traffic; polling guards against disconnects
- Interrupted download resume | undecided → `.part` via `--paths incomplete:{staging_dir}` + SQLite job persistence + `interrupted → resume` | staging_dir on persistent disk (not /tmp tmpfs), fixed naming guarantees same-param rerun hits resume
- Cookie strategy | undecided → only submit the three keys (SESSDATA/DedeUserID/bili_jct) temporarily with the job, not written to disk | satisfies HD with login state; minimal exposure, privacy first
- Quality selection | undecided → five preset tiers (auto/1080P/720P/480P/audio-only) + dynamic real list, auto tier rendered as `auto(actual highest tier)` | presets lower selection cost, the list filtered by login state via `/api/info` to guarantee real availability
- Login state | undecided → logged-in/logged-out dual mode, tier linkage disabled + degraded fallback annotation | Bilibili guest vs logged-in permission differences are significant, needs explicit distinction
- Config model | undecided → four layers: per-job > userscript GM > env/CLI > config.toml | backend controls runtime parameters (dirs/paths/concurrency/proxy), browser only stores preferences
- Authentication | undecided → local loopback listening + optional auth_token | single-machine scenario defaults to zero config, reserves protection for non-local access
- Danmaku | included in first version → excluded from first version | yt-dlp does not natively support Bilibili danmaku, needs separate backend implementation, listed for evolution
