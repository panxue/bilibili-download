# Iteration 0.2.0 — first runnable implementation

First code landed after the documentation phase (1.0.0): FastAPI backend + userscript floating panel fully implemented and verified end-to-end.

## Changes

- Backend skeleton | none → `backend/{config,db,downloader,main,urls}.py` | three-layer config, SQLite persistence, yt-dlp subprocess queue, FastAPI routes and SSE
- Job queue | none → asyncio multiple workers + `states` in-memory state + DB persistence | concurrency limited by `max_concurrent`, in-process PID held by the worker
- Progress reporting | none → yt-dlp `--progress-template` line-by-line parsing → `percent/speed/eta`, SSE `/api/jobs/{id}/stream` | contract per api.md §5, 0.5s heartbeat
- Pause semantics | none → terminate(SIGTERM) keeps paused; non-zero exit no longer misjudged as failed | first version wrongly marked paused non-zero exits as failed, fixed (state machine aligned with state-lifecycle.md)
- Resume | none → `interrupted/failed → resume_after_interrupt`, `.part` kept in staging_dir | `scan_interrupted` recovers after a power-loss restart
- Quality | none → five `QUALITY_FORMAT` tiers → `-f` expression + `/api/info` prefetch of available tiers | login-state differences greyed out by frontend `applyQualities`
- Cookie masking | none → Cookie submitted temporarily via `--add-header`, logs masked with `_mask_cookie` | privacy not written to disk, logs not leaked (fixed the leaked-log command)
- Frontend floating panel | none → single-file userscript with Shadow DOM, three tabs (new/jobs/settings) | implemented per api.md/ui.md; SSE + 2s polling fallback
- Health check | none → `/api/health` returns the envelope `{code,data}` | aligned with the api.md contract, fixed bare-object vs envelope inconsistency
