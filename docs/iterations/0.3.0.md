# Iteration 0.3.0 — high-tier quality and robustness hardening

Hardening iteration after 0.2.0 (first runnable implementation): persistent cookies, high-quality tiers, SSE/progress robustness, unified error body.

## Changes

- Cookie channel | `--add-header "Cookie: ..."` (temporary) → persistent `data/cookies.txt` (Netscape format) + `--cookies` | yt-dlp's bilibili extractor relies on a real cookie file to determine `is_logged_in`; `--add-header` cannot see the login state, quality capped at 1080P, only `--cookies` returns 8K
- Cookie validity pre-validation | none → check `/x/web-interface/nav` before `POST /api/info`, `/api/download`, `resume_after_interrupt` | invalid cookies return `code:-3` immediately, avoiding discovering failure only after download
- Quality tiers | five tiers (auto/1080/720/480/audio) → added 2K/4K/8K/360P + arbitrary `NNN P` | requirement demands 8K support, `quality_to_format()` regex fallback for any height
- Progress staging path | `--paths incomplete:` → `--paths temp:` | yt-dlp only recognizes `home/temp` (`incomplete` invalid), fixed after error observed in testing
- Progress line parsing | strict `download:` prefix → lenient regex | real output may be bare `0.0%|...` (no prefix), old regex would miss it
- SSE payload | flat `{percent,speed,eta}` → nested `progress:{percent,speed,eta}` | aligned with the api.md contract, frontend `j.progress.percent` access consistency
- Terminal-state handling | mixed dict/object attribute access → `to_api()` uniformly handles dict/object | SSE once raised `TypeError` reading DB rows (dict)
- Output path | only `Destination:` → added capture of `[MoveFiles] Moving ... to "..."` | final path during merge determined by MoveFiles, Destination may only be temporary
- Error responses | bare/scattered → global `HTTPException` handler unifies `{code,msg}` | 401→`-401`, 404→`-404`, 409→`-409`; frontend only recognizes `code===0`/`-401`
- Job deletion | frontend self-decides deletion → backend-authoritative `DELETE /api/jobs/{id}` | state-machine deletion belongs to backend, frontend only calls, never decides; busy 409, missing 404
- Resume scope | `interrupted/failed` → added `canceled` | after user cancel, re-downloading with the same params needs no new job, resume directly
- Job title | only `P{n}` → `{video title} P{n}` | `DownloadBody.title` passed in from the floating panel, multi-P distinguishable in the list
- Userscript cookie reading | `document.cookie` → `GM_cookie` (fallback `document.cookie`) | SESSDATA is HttpOnly, `document.cookie` cannot read it
- Initialization | none → `unsafeWindow.__INITIAL_STATE__` | the userscript sandbox isolates page globals, needs `unsafeWindow` to bypass

## TODO / rollback notes

- The persistent cookie file solution does not send `--cookies` for **anonymous jobs** (no cookies), guest downloads still work normally.
- Known boundaries: `GM_cookie` callback requires browser authorization confirmation; automatically falls back to `document.cookie` when not supported (prompts not-logged-in when SESSDATA cannot be read).
