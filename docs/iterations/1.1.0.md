# Iteration 1.1.0 — Docker Hub publish + env-driven package index

## Changes

| Topic | Before → After | Reason |
|-------|----------------|--------|
| Package index in Dockerfile | hardcoded `pypi.tuna.tsinghua.edu.cn` (`ENV UV_DEFAULT_INDEX` + pip `-i`) → build args `UV_DEFAULT_INDEX` / `PIP_INDEX_URL` defaulting to official PyPI | the repo is public, so a China-specific mirror must not be hardcoded; the index becomes an injectable build-time/CI choice (official PyPI for GitHub runners, Tsinghua for mainland local builds via `.env`) |
| Package index in pyproject.toml | `[[tool.uv.index]]` pinned Tsinghua as default → removed, uv defaults to official PyPI | keeps the repo source-agnostic; local restricted networks set `UV_DEFAULT_INDEX` in the shell as documented in AGENTS.md |
| Package index in compose.yaml | none (mirror baked into the image) → `build.args` reads `UV_DEFAULT_INDEX` / `PIP_INDEX_URL` from the same `.env` file that supplies `BLDLP_*` | mirrors are a build-time concern, so they ride the same per-machine `.env`; runtime `env_file` stays unchanged |
| CI (ci.yml) | lint + test only → adds a `docker-publish` job on `main`: login to Docker Hub (`DOCKERHUB_USERNAME`/`DOCKERHUB_TOKEN` secrets) + `docker/build-push-action` pushing `latest` and `1.1.0` tags | the image is now public distribution (matches AGENTS.md/design.md) instead of purely local in-place builds |
| CI sync env | `UV_DEFAULT_INDEX=https://pypi.org/simple` override (had to fight the pyproject pin) → removed, default is already official PyPI | the pyproject pin no longer exists, so the override is dead config |
| Version | pyproject / userscript / `/api/health` `1.0.0` → `1.1.0` | minor feature increment: new distribution path (Docker Hub) is user-visible |

## Implementation notes

- Dockerfile `ARG` placement matters: `ARG` declared before the first `FROM` is in the global scope but must be re-declared inside each stage; the builder stage re-declares `ARG UV_DEFAULT_INDEX` and the runtime stage `ARG PIP_INDEX_URL`, each consuming its own layer's installer (uv vs pip).
- `.env.example` documents both mirror keys so mainland users can opt in without editing repo files.
- The `docker-publish` job runs only on `push` to `main` (not PRs); it does not `needs: test` so a failed lint/test run does not silently skip publishing — the image build itself re-resolves all deps, acting as its own check.
- Secrets referenced: `DOCKERHUB_USERNAME` + `DOCKERHUB_TOKEN` (both configured as Actions secrets).
